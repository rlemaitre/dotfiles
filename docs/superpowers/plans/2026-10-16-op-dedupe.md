# op-dedupe Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A command, `op-dedupe`, that finds duplicate 1Password logins, prints a dry-run plan, and with `--apply`
merges each group into one kept copy and archives the rest.

**Architecture:** A small Python package installed by chezmoi to `~/.local/lib/op_dedupe/`, with a thin executable at
`~/.local/bin/op-dedupe`. Pure modules (grouping, item parsing, planning, merging, report) are unit-tested with made-up
JSON; one module wraps the `op` CLI. The dry run and the apply step share one planner.

**Tech Stack:** Python 3.12 standard library only (`unittest`, `subprocess`, `concurrent.futures`, `dataclasses`),
`op` 2.41.0 from mise.

**Spec:** `docs/superpowers/specs/2026-10-16-op-dedupe-design.md`

## Global Constraints

- Standard library only; no `pip` or `uv` dependency.
- No password, 2FA secret or other field value in stdout, stderr, files, logs, exception messages or `op` arguments.
  Values reach `op` only through stdin.
- Never archive or delete an item in a shared vault unless the kept copy of its group is in that same vault.
- Never archive a copy before the kept copy is re-fetched and every merged value is confirmed present.
- Removal is `op item delete --archive` only.
- The personal vault is `Private`. If no vault has that name, stop with an error before planning.
- Public repo: no real vault names (other than `Private`), sites, usernames or ids in code, tests, docs or commits.
  Test data uses `example.com`-style values.
- Immutable data: frozen dataclasses; functions return new values, never mutate their inputs (the user's coding rule).
- `PYTHONDONTWRITEBYTECODE=1` when tests run, so no `__pycache__` lands in `home/` (chezmoi would install it).
- `mise run check` passes before every commit. Commit messages: `<type>: <description>`, no attribution lines.

## Review Focus

1. **`repr` or an exception carrying a secret.** A dataclass holding a password prints it in a traceback. Secret
   fields use `field(repr=False)`, and tests assert `repr()` lacks them (Task 2).
2. **A run interrupted mid-group** (Ctrl-C after the merge, before archiving). The next run must see the group again,
   plan no additions, and archive the rest (Task 3, `test_already_merged_group_has_no_additions`).
3. **The same 2FA secret written two ways** (an `otpauth://` URI and a bare secret, or different spacing or case).
   Comparing raw values would flag a false conflict; compare the `secret` parameter, uppercased, spaces removed
   (Task 3).
4. **A work account whose personal vault is not called `Private`** (for example on nabla-mac-raphael). Every vault
   would count as shared. The script stops instead (Task 5, `test_missing_private_vault_stops`).
5. **Custom fields with the same label in different sections.** Matching on label alone would merge or flag the wrong
   fields; the key is (section label, field label) (Task 3).

### Task 3: Planner

**Files:**
- Create: `home/dot_local/lib/op_dedupe/planner.py`
- Create: `tests/op_dedupe/test_planner.py`

**Interfaces:**
- Consumes: `Item`, `Field` (Task 2).
- Produces:
  - `Additions(notes: str | None, otps: tuple[Field, ...], urls: tuple[str, ...], tags: tuple[str, ...],
    custom: tuple[Field, ...])`: frozen; `notes` has `repr=False`. `is_empty() -> bool`. `names() -> tuple[str, ...]`:
    human labels for the report, such as `"notes"`, `"2FA code"`, `"URL"`, `"tag"`, `"field <section>/<label>"`.
  - `Plan(keeper: Item, additions: Additions, archive: tuple[Item, ...])`: frozen.
  - `Flag(reason: str, items: tuple[Item, ...])`: frozen. Reason constants: `DIFFERENT_PASSWORDS`,
    `CONFLICT_NOTES`, `CONFLICT_OTP`, `CONFLICT_FIELD`, `SEVERAL_SHARED_VAULTS`, `ATTACHMENT_OR_PASSKEY`,
    `PASSKEY_ON_KEEPER`, `FETCH_FAILED`.
  - `plan_group(items: tuple[Item, ...], personal_vault: str = "Private") -> Plan | Flag`.

Rules, checked in this order (the first flag wins):
1. Copies in two or more vaults other than `personal_vault`: `SEVERAL_SHARED_VAULTS`.
2. Passwords (exact, empty included) differ between any two copies: `DIFFERENT_PASSWORDS`.
3. Keeper: among copies in the shared vault if there is one, else all copies, the latest `updated_at`; ties go to the
   lowest `id`.
4. Any copy to archive has `has_files` or `has_passkey`: `ATTACHMENT_OR_PASSKEY`.
5. Notes: compared trimmed. Two different non-empty values among all copies: `CONFLICT_NOTES`. Keeper empty and
   another not: added.
6. 2FA: compared by OTP key: the `secret` query parameter when the value is an `otpauth://` URI, else the value;
   uppercased, spaces removed. Two different keys: `CONFLICT_OTP`. Keeper has none, another has one: added.
7. URLs: other copies' URLs missing from the keeper, compared by the full trimmed `href`: added. Tags: union.
8. Custom fields keyed by (section label, field label), values trimmed. Same key, different values: `CONFLICT_FIELD`.
   Missing in the keeper: added.
9. Additions not empty and the keeper has `has_passkey`: `PASSKEY_ON_KEEPER`.

  `test_several_shared_vaults_flagged`, `test_different_passwords_flagged`, `test_shared_copy_is_kept`,

- Produces, in `opcli.py`:
  - `class OpError(Exception)`: message is the `op` subcommand, the item id and the exit code, plus `op`'s stderr

  - `list_vaults() -> list[dict]`, `list_logins() -> list[dict]`, `get_item(item_id: str, vault_id: str) -> dict`

### Task 6: `--apply`

Blocked until Task 1 found a passkey marker.

**Files:**
- Create: `home/dot_local/lib/op_dedupe/merge.py`
- Modify: `home/dot_local/lib/op_dedupe/opcli.py`, `home/dot_local/lib/op_dedupe/cli.py`
- Create: `tests/op_dedupe/test_merge.py`
- Modify: `README.md` (row `| Merge and archive duplicate 1Password logins | \`op-dedupe --apply\` |`)

**Interfaces:**
- Consumes: `Plan`, `Additions` (Task 3), `parse_item` (Task 2), `build_plan`, `main` (Task 5).
- Produces, in `merge.py`:
  - `apply_additions(raw: dict, additions: Additions) -> dict`: a new item JSON (deep copy). Notes go in the `NOTES`
    field; URLs are appended non-primary; tags are added; OTP and custom fields are appended as new fields with fresh
    unique ids, and a section missing from `sections` is created.
  - `missing_after_merge(fresh: Item, additions: Additions) -> tuple[str, ...]`: the `names()` of additions not found
    in the re-fetched keeper, compared as in the planner.
- Produces, in `opcli.py`: `edit_item(item_id: str, vault_id: str, item: dict) -> None` (JSON on stdin to
  `op item edit <id> --vault <vault_id>`) and `archive_item(item_id: str, vault_id: str) -> None`
  (`op item delete <id> --vault <vault_id> --archive`).
- In `cli.main`, `--apply`: build the plan from a fresh fetch, print the counts, read one line from stdin and continue
  only on exactly `yes`. Then for each plan (the first N with `--limit N`): if additions are not empty, `edit_item`,
  `get_item` again, and stop the whole run with exit code 1 and the group's site and username if
  `missing_after_merge` is not empty; then `archive_item` each copy to archive. Print `Done: N groups, M items
  archived`.

  - `test_apply_additions_round_trip`: `missing_after_merge(parse_item(apply_additions(raw, additions)), additions)`
