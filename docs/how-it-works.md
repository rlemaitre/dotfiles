# How it works

## The layers

| Layer | Manages | Declared in |
|---|---|---|
| chezmoi | files in `~`, per-machine templates, setup scripts | `home/` |
| mise | command-line tools, language runtimes, npm/go/pipx tools | `packages.yaml` → `mise` |
| Homebrew | formulae mise cannot install, casks (apps, fonts), third-party taps | `packages.yaml` → `brew` |
| `mas` | App Store apps | `packages.yaml` → `mas` |
| `gh` | GitHub CLI extensions and agent skills | `packages.yaml` → `gh_extensions`, `gh_skills` |
| rustup | Rust components (`rust-analyzer`) | `packages.yaml` → `rustup_components` |
| `pluginkit` | Quick Look preview extensions | `packages.yaml` → `quicklook_extensions` |
| `defaults`, `pmset` | macOS settings | `macos_defaults.yaml` |

All of them are driven by chezmoi: a change to a data file changes the rendered text of a setup script, and
chezmoi runs that script on the next `chezmoi apply`. [Tools](tools.md) lists every entry.

## Install policy

A tool has **one channel**, chosen in this order:

1. **mise**: the registry first, then the `npm:`, `pipx:`, `go:` and `github:` backends;
2. a **Homebrew formula**, when mise cannot install it (or when something else needs it from brew);
3. a **cask**, for GUI apps and fonts;
4. **`mas`**, for App Store apps with no cask.

`scripts/check-packages.sh` (part of `mise run check`) fails when a name appears in two of mise, formulae and
casks on the same machine. Tools that stay on brew on purpose: `mise` itself (it cannot install itself), `usage`, `bash`,
`coreutils`, `gnupg`, `pinentry-mac`, `postgresql@18`, `mas`, `buku`, `jdtls`.

Exceptions, each documented where it lives:

- **Mason** installs Neovim's language servers (the LazyVim default). The servers Claude Code also needs
  (pyright, gopls, lua-language-server) come from mise and Neovim is told to use them.
- **rust-analyzer** is a rustup component, because the rustup shim in `~/.cargo/bin` shadows a mise copy.
- **kotlin-lsp** is installed by a script while the Homebrew formula is broken ([upstream watch](upstream-watch.md)).
- Apps no channel can install: [manual installs](manual-installs.md).

## The chezmoi source

`.chezmoiroot` contains `home`, so `home/` is the source directory and the repo root stays free for scripts and docs.
`~/.config/chezmoi/chezmoi.toml` is generated by `chezmoi init` from `home/.chezmoi.toml.tmpl`; it stores the source
path and the machine data (see [per-machine data](#per-machine-data)).

### File names

chezmoi reads attributes from name prefixes and suffixes. The ones used here:

| In the repo | Becomes in `~` |
|---|---|
| `dot_zshenv` | `.zshenv` (`dot_` is a leading dot) |
| `dot_config/git/config.tmpl` | `.config/git/config`, rendered as a Go template |
| `private_dot_ssh/` | `.ssh/` with mode 700 (`private_` on a file means 600) |
| `executable_foo.sh` | `foo.sh` with mode 755 |
| `readonly_dot_x` | `.x` without write permission |
| `create_private_settings.json` | `settings.json`, **created only if missing, never overwritten** |
| `run_onchange_after_20_x.sh.tmpl` | a script run when its rendered text changed |
| `run_after_50_x.sh.tmpl` | a script run on every apply |

Other special files in `home/`: `.chezmoiignore` (targets to skip, can be templated per machine),
`.chezmoiremove` (targets chezmoi deletes; add a path here when a file leaves the repo and must also leave the Macs),
`.chezmoidata/` (data available to every template).

### Files an application rewrites

Some apps rewrite their own config. If such a file were a normal managed file, the next `chezmoi apply` would stop with
"has changed since chezmoi last wrote it". Two treatments:

- a **`create_` seed** for a file the app owns: `~/.claude/settings.json` (Claude Code edits it when plugins change);
- a normal managed file, with `chezmoi re-add <file>` after each in-app change: `gh` and glow configs, Neovim's
  `lazyvim.json` and `lazy-lock.json`;
- a template, for Zed's `settings.json`: its `javaHome` comes from the java pin of each Mac. `re-add` skips templates,
  so after an in-app change run `chezmoi merge ~/.config/zed/settings.json` and keep the change in the `.tmpl`.

## Per-machine data

`home/.chezmoi.toml.tmpl` lists the known hosts (`athena`, `nabla-mac-raphael`), refuses any other hostname, and asks:

| Question | Stored as | Used by |
|---|---|---|
| Git email | `.email` | `git/config` (`user.email`) |
| SSH key file name in `~/.ssh` | `.ssh_key` | `git/config` (`sshCommand`), `ssh/config` (`IdentityFile`) |
| GPG signing key id | `.gpg_key` | `git/config` (signing); empty means no signing |

Templates also see `.machine`. In the data files each section has three keys: `common` (both Macs), `athena` and
`nabla-mac-raphael`; every key must exist in every section, even empty. `tests/<hostname>.toml` are fixtures used by
`mise run check` to render every template for both machines without a real Mac.

## Data files

`home/.chezmoidata/packages.yaml`:

| Key | Meaning |
|---|---|
| `mise` | tools, always pinned as `name@version` (checked) |
| `brew.taps`, `brew.formulae`, `brew.casks` | Homebrew; listed taps are tapped and trusted before the bundle |
| `mas` | App Store apps as `id: name` |
| `gh_extensions`, `gh_skills` | GitHub CLI extensions (`repo`, `pin`); Claude Code skills (`repo`, `skill`, `pin`) |
| `kotlin_lsp` | version, URL and checksum of the stopgap install |
| `rustup_components` | rustup components |
| `quicklook_extensions` | extension id, bundle path, `use` or `ignore` |

`home/.chezmoidata/macos_defaults.yaml`:

| Key | Meaning |
|---|---|
| `macos_defaults` | `defaults write` entries (`domain`, `key`, `type`, `value`; `host: true` for `-currentHost`; `type: dict` for bool dicts; `protected: true` for privacy-protected domains, which only warn when the write fails) |
| `macos_defaults_absent` | keys to delete (undoes older overrides) |
| `macos_power` | `pmset` values (athena only today) |

## The setup scripts

`chezmoi apply` runs the `before` scripts, writes the files, then runs the `after` scripts. Within a phase they run in
numeric order. `onchange` scripts run only when their rendered text changed, so each one embeds the data it depends on.

| Script | Runs | What it does |
|---|---|---|
| `10_brew-bundle` | on change | taps and trusts the listed taps, then `brew bundle --no-upgrade` |
| `20_mise-install` | on change | `mise install` for the tool list |
| `22_rustup-components` | on change | `rustup component add` |
| `25_gpg-reload` | on change | restarts gpg-agent after its config changes |
| `30_mas` | on change | installs the missing App Store apps |
| `35_docker-plugins` | always | links the compose and buildx binaries into `~/.docker/cli-plugins` |
| `45_kotlin-lsp` | on change | downloads and checks JetBrains' server archive (stopgap) |
| `46_bat-cache` | on change | `bat cache --build` for the Catppuccin themes |
| `47_zsh-completions` | on change | generates completion files for mise tools |
| `50_gh-extensions` | always | installs the `gh` extensions at their pinned tag (reinstalls when it changes) and the skills, once `gh` is logged in |
| `52_workspace` | always | clones the private `rlemaitre/workspace` repository to `~/Developer/workspace` when it is missing (needs `gh` logged in), never pulls or overwrites |
| `55_quicklook-extensions` | always | registers the Quick Look extensions and sets use or ignore |
| `60_sudo-touchid` | always | enables Touch ID for `sudo` (needs a terminal) |
| `70_macos-defaults` | on change | writes the defaults, deletes the absent keys, restarts Dock, Finder and the menu bar |
| `75_macos-power` | always | applies the `pmset` values when they differ (needs a terminal) |
| `80_colima-agent` | on change | loads the LaunchAgent that starts Colima at login |
| `85_maintain-agent` | on change | loads the LaunchAgent that runs the [weekly upkeep](maintenance.md#weekly-upkeep-on-each-mac) |
| `86_standup-brief-agent` | on change | loads the LaunchAgent that runs the [standup brief](maintenance.md#standup-brief-work-mac) on weekdays (work Mac only) |

"Always" scripts check first and do nothing when the Mac already matches, so they are safe to run repeatedly.

## The shell

`~/.zshenv` sets the XDG variables and `ZDOTDIR=~/.config/zsh`. `~/.config/zsh/.zshrc` then runs, in this order:

1. Homebrew's environment, then **mise activation** (everything after it can use mise tools);
2. `theme.zsh`: picks Latte or Mocha from the macOS appearance and exports the variables the tools read;
3. zinit and its plugins (completions, autosuggestions, fzf-tab, gpg-agent, Oh My Zsh snippets, atuin);
4. the generated completions on `fpath`, then `compinit`;
5. the oh-my-posh prompt (in Ghostty), keybindings, history, zoxide, `aliases.zsh`, `env.zsh`;
6. **zsh-syntax-highlighting last**, because it wraps the editor widgets created before it.

`aliases.zsh` holds small wrappers (`glow`, `lazydocker`) that need a setting only for one call.
`env.zsh` sets `EDITOR`, `MANPAGER` (through bat), `DOCKER_HOST` (the Colima socket) and the GPG/SSH agent.

## What is deliberately not managed

- **Credentials and identity**: SSH and GPG keys, `~/.docker/config.json`, `~/.claude.json`, GitHub Copilot's `apps.json`.
- **State and caches**: `~/.cache`, `~/.local`, shell histories, Raycast's data, `~/.npm`, `~/.gradle`.
- **App-owned settings** in `~/Library`.
- **The contents of `~/Developer/workspace`**: it is its own private repository, cloned once by script 52. Its projects stay local to each Mac.
- **Apps you launch from `~/Applications`** (JetBrains IDEs through Toolbox, Steam games).

## Safety nets

- The pre-rewrite content of this repo is on the branch `backup/pre-rewrite-2026-10-11`.
- Before the cutover on athena, a tarball of the old config was written to `~/Backups/dotfiles-cutover-2026-10-11.tar.gz`
  (restore with `tar -xzf <file> -C ~`; it overwrites real files).
- `chezmoi diff` shows every change before `chezmoi apply` makes it.
